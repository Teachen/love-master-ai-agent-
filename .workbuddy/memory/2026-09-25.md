### 实测发现的三个真实缺陷（均已修复）

1. **H5 端底部输入框被顶出屏幕**
   - 根因：uni-app 在 H5 把导航栏渲染成页面内真实元素，占约 44px 文档流高度；
     `.chat-room` 用 `height: 100vh` 导致容器比可视区高出一截
   - 修复：`/* #ifdef H5 */ height: calc(100vh - var(--window-top, 0px) - var(--window-bottom, 0px))`
   - 验证：探针实测 `scrollHeight == innerHeight`，`overflowV=0`

2. **流式长回复看不到最新内容（滚动贴底不可靠）**
   - `scroll-into-view` 指向最后一条消息 → 对齐元素顶部，只看到开头
   - `scroll-into-view` 指向末尾空锚点 → 只能贴到大致底部
   - `scroll-top` 设超大值 → **H5 端失效**：实测结束后 `top=381 / max=715`
   - 定稿：H5 直接操作真实滚动容器，`nextTick` 后 `el.scrollTop = el.scrollHeight`
   - 关键坑：`<scroll-view>` 在 H5 渲染成**两层同名** `.uni-scroll-view`，
     `querySelector` 会命中外层（不滚动的那层）。改为遍历后按 `getComputedStyle().overflowY` 挑 `auto|scroll` 的那层
   - 验证：实测 `top=856 / max=856 / atBottom=true`
   - 补充：`finishAi()` 里再滚一次（去掉打字光标后文字会重新折行）

3. **`.env` 注入验证**
   - 用 `--mode staging` 构建，确认产物里出现 staging 地址，证明 mode 覆盖生效

## 追加二：HBuilderX 报「node_modules缺少编译器模块」根因定位（已解决）

### 报错原文
```
11:38:17.520 node_modules缺少编译器模块，请执行npm install后重试
11:38:17.520 项目 uniapp 编译失败。
```

### 根因（唯一）：`src/manifest.json` 缺 `"vueVersion": "3"`

反编译 `D:\program\HBuilderX\plugins\uniapp-extension\out\index.js` 还原出 HBuilderX 的判定链：

| 步骤 | 函数 | 依据 | 本项目 |
|---|---|---|---|
| ① | `getIsCli(projectDir)` | `package.json`+`src/manifest.json`+`src/pages.json`+`src/App.vue`+`src/main.js` 齐全 | true → 走 CLI 分支 |
| ② | `getVueVersion()` | **读 `src/manifest.json` 的 `vueVersion`**，读不到回退 `"2"` | 改前 undefined → `"2"` ❌ |
| ③ | `getCompilePlugin()` | CLI+Vue2 → `node_modules/@vue/cli-service` | 该包不存在 |
| ④ | `existsSync(③)` | false → 报「node_modules缺少编译器模块」 | ✅ 报错复现 |

同理 `getCompileFile()`：CLI+Vue3 → `./bin/uni.js`；CLI+Vue2 → `./bin/vue-cli-service.js`。

**命令行为什么能跑**：`npm run dev:*` 执行 `@dcloudio/vite-plugin-uni/bin/uni.js`，走纯 CLI 逻辑，
**不读 `vueVersion`**。两条路径入口不同 → 一边通一边不通。

**修复**：`src/manifest.json` 顶层加 `"vueVersion": "3"`（已改）。

> CLI 工程判 Vue3 需**同时**满足 `vueVersion === "3"` 且根目录存在 `vite.config.js`/`vite.config.ts`。
> 本项目 `vite.config.js` 本来就有，只差这一个字段。
> 注意枚举值是字符串 `"2"`/`"3"` —— 第一版复刻脚本误用 `'vue2'`/`'vue3'` 导致误判，已纠正。

### 验证（双重）
1. 复刻判定链：`getVueVersion()` → `"3"`，`getCompilePlugin()` → `@dcloudio/vite-plugin-uni`（存在），

## 追加四：修复「APK 装到手机提示后端未连接」

### 现象
打包 APK 装到安卓手机 → 首页 toast「后端未连接，请先启动服务」。

### 根因（单一）
`.env.production` 里 `VITE_API_BASE_URL=http://localhost:8000/api`。
**App 上的 localhost 指手机自己**，不是开发电脑 → 必然连不上。

### 排查证据（后端侧其实完全正常）
| 检查项 | 结果 |
|---|---|
| 后端 `.env` 的 `HOST` | `0.0.0.0` ✅ 已监听所有网卡 |
| `curl 127.0.0.1:8000/api/health` | HTTP 200 ✅ |
| `curl 192.168.31.172:8000/api/health` | **HTTP 200 ✅ 局域网可达** |
| 后端 CORS | `cors_origins=["*"]` ✅ |
| 本机 WLAN IP | `192.168.31.172` |

> 取本机 IP 的坑：Git Bash 下 `ipconfig \| grep IPv4` 因中文编码匹配不到，
> 用 `node -e "os.networkInterfaces()"` 才稳。

所以问题 100% 在前端打包时写死的地址。

### 修复（5 处改动）
1. **`.env.production`**：两行 `localhost` → `192.168.31.172`
2. **`manifest.json`**：`app-plus.distribute.android.usesCleartextTraffic: true`
   —— Android 9+ 默认禁止明文 HTTP，不开会报 `net::ERR_CLEARTEXT_NOT_PERMITTED`。
   该字段虽不在 uni-app 官方字段表里，但 DCloud 官方问答确认可用。
3. **`src/config/index.js`**：新增运行时可覆盖地址
   `getServerBase()` / `setServerBase()` / `isCustomServer()` / `DEFAULT_SERVER_BASE`，
   存 `uni.setStorageSync('LM_SERVER_BASE')`，优先级高于 `.env` 编译值
4. **`http.js` / `sse.js`**：由「引用编译期常量」改为「每次请求/建流时调 `getServerBase()`」
   → App 内改完地址**立即生效、无需重启**（常量方案必须重启 App）
5. **`pages/index/index.vue`**：首页右上角 ⚙ 设置弹层（改地址 / 恢复默认 / 保存并重连）

### 为什么要做运行时配置
电脑 IP 由路由器 DHCP 分配，换网络就会变。写死在 `.env` 里意味着
**每次 IP 变化都得重新云打包**，成本极高。做成 App 内可改，一次打包长期可用。

### 验证（三重）
1. 三端构建全通过（app / mp-weixin / h5）
2. 产物断言：App 与小程序产物中均只有 `http://192.168.31.172:8000/api`，
   **无 localhost 残留**；运行时逻辑 `LM_SERVER_BASE` 已打进 `app-service.js`

## 追加八：环境变量生效，但 /docs 打不开 → Swagger UI 静态资源自托管

## 追加十：App 端连不上的真正根因 —— 逻辑层无 XHR/EventSource（重大跨端缺陷）

### 关键证据
用户截图显示 App ⚙ 弹层「当前生效」=「编译默认」= 正确域名 → **排除地址问题**。

### 真正根因（此前一直被掩盖）
uni-app 编译到 App 后，业务 JS 运行在**独立逻辑层（V8/JSCore）**，
视图层 WebView 只负责渲染 —— 逻辑层里**没有 XMLHttpRequest、fetch、EventSource**。

| 层 | 依赖 | 状态 |
|---|---|---|
| http.js（axios） | XMLHttpRequest | ❌ 只有 `#ifdef MP-WEIXIN` 装了适配器，App 端缺失 |
| sse.js（SSE） | EventSource | ❌ 错误假设「App 运行在 WebView 同 H5」，App 端直接 `new EventSource` 崩 |

→ H5 正常、小程序正常、**App 端所有请求必然失败**，换任何地址都无用。
这是 App 端「从第一天起就不可能连上后端」的缺陷，之前被「地址不对」的表象掩盖。

### 修复
1. `src/api/http.js`：新增 `#ifdef APP-PLUS` 的 `uniRequestAdapter`（axios adapter 协议）：
   自己拼 baseURL + params；AxiosHeaders.toJSON() 转普通对象；
   非 2xx reject 时**带 error.response**（响应拦截器能取 detail）；fail 带 errMsg
2. `src/utils/sse.js`：
   - createSse 路由改为 H5 / APP-PLUS / MP-WEIXIN 三分支
   - 新增 `_createPlusSse`：`plus.net.XMLHttpRequest` open→send，
     readyState 3/4 时 diff responseText 增量喂 SSE 帧解析（复用 data: 帧逻辑），
     支持 abort、4xx/5xx 判失败、onerror 兜底
   - 修正注释（App 端机制说明）

### 三端产物验证（grep）
- App：`plus.net.XMLHttpRequest` ✅ 1 处；`new EventSource` **0 处**；adapter 在 ✅
- H5：`new EventSource` 在 `assets/ChatRoom.*.js` ✅
- MP：`enableChunked` 在 `utils/sse.js`（注意**不在** vendor.js）✅

### 复用要点（重要）
- **uni-app App 端（vue3）= 逻辑层 V8 + 视图 WebView 分离**，浏览器 API（XHR/ES/fetch/DOM）
  一律不存在；需要 XHR 语义用 `plus.net.XMLHttpRequest`（5+ API，逻辑层可调）
- axios 上 App 端必须给 adapter；SSE 上 App 端用 plus.net.XMLHttpRequest 增量读 responseText
- 「换地址也连不上」时应怀疑**传输层**而非地址本身

### 追加：导出仍 404（二次）→ 前端拼接 URL 真 bug
- 用户截图：浏览器直接显示 `{"detail":"Not Found"}` —— 下载地址拼错了
- 根因 1（URL 拼接）：`getServerBase()` 返回 `http://localhost:8000/api`（带 /api 前缀），
  后端返回的 `res.url` 是 `/api/files/xxx.pdf`（已含 /api）→ 拼成 **/api/api/files/...** 404
- 根因 2（H5 下载）：跨域 `<a download>` 的 download 属性**会被浏览器忽略**并直接导航，
  于是 404 JSON 直接渲染在页面上（用户看到的截图）
- 修复：
  1. `config/index.js` 新增 `getServerOrigin()`：正则提取 `https?://host[:port]`，
     （小程序无 URL 构造器，不能 new URL()）
  2. `history.vue` 下载地址改 `getServerOrigin() + res.url`；
     H5 分支改 **fetch → blob → objectURL → a[download]**（同源 blob 才真正落盘）
- 验证：三端 build DONE；H5 chunk 含 createObjectURL；dev 产物含新逻辑；后端 health 200
- 教训：
  - **返回「绝对路径」+ 前端「带前缀 base」拼接 = 双前缀陷阱**，拼 URL 前先想清楚两边各自含什么
  - **跨域 a[download] 无效**是 H5 下载的经典坑，必须 blob 化
  - 用户看到「浏览器直接渲染 404 JSON」= 导航到了错误 URL，而非接口调用失败
