# 2026-09-26 工作日志

## 账号体系（手机号 / 微信登录）设计与实现

### 背景
用户需求：实现账号绑定功能同步用户数据、手机号登录注册、小程序授权登录，并调研 App 微信登录可行性。

### 政策核实（决定性前提）
- **个人主体小程序**：`wx.login` 静默登录可用；但**无 `getPhoneNumber`**、**无 UnionID**
  （微信开放平台绑定需开发者资质认证，而个人类型账号暂不支持微信认证）、**婚恋交友/AI 生成内容类目个人主体不可选**。
- **手机号一键登录**：需非个人主体 + 微信认证 300 元/年 + 付费 0.03 元/次（前 1000 次免费）。
- **App 移动应用微信登录**：个人账号无法申请，需企业/组织认证；Android 要包名 + **32 位 MD5 签名**，iOS 要 Bundle ID + Universal Links。
- 结论：主体升级（推荐个体工商户）是绕不开的前提；未升级时走「手机号+短信验证码」自建账号方案。

### 实现内容
后端（新增）：
- `app/db/models.py`：`User` / `UserIdentity` / `SmsCode` 三表。身份表唯一键 **(provider, app_id, open_id)**
  —— 微信 openid 只在单个应用内唯一，必须带 app_id。
- `app/core/auth.py`：**手写 HS256 JWT**（标准库 hmac+hashlib，不引 PyJWT）、手机号工具、`get_current_user_id` / `get_optional_user_id` 依赖。
- `app/api/auth.py`：`/config` `/sms/send` `/login/phone` `/login/wechat` `/bind/phone` `/merge-guest` `/me` `/profile` `/logout`；
  含腾讯云短信 TC3-HMAC-SHA256 签名实现（未配置时走 dev 模式回显 devCode）。
- `app/config/settings.py`：account 配置段（jwt_secret / sms_* / tencent_* / wechat_miniapp_*）。
- `app/api/history.py`：`user_id` 改为 **登录态优先**，游客只能操作 guest 空间（越权防护）。
- `app/core/middleware.py`：`/api/auth` 加入免产品级 API Key 白名单（否则登录形成死锁）。

前端（新增/改造）：
- `uniapp/src/utils/authStore.js`：登录态 + **设备级游客空间**（`guest-<hex>`，替代原来所有人共用的 `default`）+ legacy 合并标记。
- `uniapp/src/api/auth.js`、`uniapp/src/api/http.js`（注入 Authorization + 401 自动清登录态）。
- `uniapp/src/pages/login/login.vue`：一页两态（登录表单 / 账号管理），含协议勾选、倒计时、devCode 提示、绑定手机号、退出登录。
- `uniapp/src/pages/index/index.vue`：新增账号状态条 + 后端连接状态条；`pages.json` 注册登录页。
- `uniapp/src/api/index.js`：历史接口统一带 `user_id=getGuestId()`。

### 关键设计决策
1. **账号与登录方式解耦**（user + user_identity），支持后续加公众号/App 登录而不改表。
2. **注册与登录合一**：查不到手机号身份就建号。
3. **绑手机号冲突规则**：手机号已被占用时，仅当**当前账号是空壳**（无其他登录方式、无对话历史）
   才自动并入手机号账号（`switched=true`，须用返回的新 token 覆盖本地）；否则 409 拒绝，绝不静默吞数据。
4. **登录不丢历史**：登录时把游客空间（含历史 `default`）迁移到账号。
5. 用户归属：带 token 时以 token 为准（忽略请求里的 user_id）；游客只能访问 `default`/`guest-*`；跨用户访问返回 404 不返回 403（不泄露存在性）。

### 测试修复的真实缺陷
1. **未登录游客可伪造 `user_id` 写进任意账号空间** → `_owner()` 加 guest 白名单校验（403）。
2. **`guestSpacesToMerge()` 顺序错误**：先读 legacy 标记、后调 `getGuestId()`，
   首次运行时 `default` 被漏掉，游客数据迁不过去 → 调整为先 `getGuestId()`。
3. **`_consume_code` 提示文案误导**：验证码已用过却提示"请先获取验证码" → 区分两种情形。
4. **绑定手机号合并规则设计缺陷**：原判定"目标账号是否空壳"，正确应为"当前账号是否空壳"
   （可能被吞掉的是当前账号的数据）。

## 环境配置分层（开发 / 预发 / 生产）

### 背景
原状态：只有一个 `.env`（内容是 `APP_ENV=prod`、`DEBUG=false`），本地开发却套着生产配置。

### 后端实现
- `app/config/settings.py` 改造为分层加载：**`.env` → `.env.<APP_ENV>` → 系统环境变量**（后者覆盖前者）。
- `APP_ENV` 解析优先级：系统环境变量 > `.env` 里的值 > `dev`；支持 16 个别名（`development`/`production`/`cloudrun`…）。
  实现要点：**必须在 `BaseSettings` 定义之前就把 `APP_ENV` 读出来** —— `env_file` 是类属性、在类定义时求值。
- 项目根定位用「`requirements.txt` 存在 + `app/` 是目录」双条件向上查找，不用 `Path.cwd()`（uvicorn/测试/IDE 工作目录各不相同）。
- 环境文件：`.env.dev`、`.env.prod`（均入库且**禁止写密钥**）；`.env` 不入库、放密钥。
- 启动横幅显示「运行环境 + 实际加载的配置文件」，排查配置不生效时第一眼看这里。
- 新增 `GET /api/health/config` 自检接口（不含密钥）。
- 告警分双通道：`config_warnings`（可公开，进接口）/ `jwt_warning`（**仅服务端日志**）。
  原因：「你在用内置默认 JWT 密钥」一旦对外暴露，等于告诉攻击者可以拿源码伪造 token。
- 生产安全拦截：`sms_dev_code_exposed = 开发模式短信 AND (非生产 OR 显式放行)`；
  `APP_ENV=prod` + `SMS_PROVIDER=none` 时 `/api/auth/sms/send` 直接 503，不回显验证码。

### 前端实现
- 环境文件：`.env.development` / `.env.production` / `.env.staging` / `.env.e2e`（+ `.env.example` 模板）。
- `package.json` 新增 `*:staging` / `*:e2e` 脚本别名（`--mode xxx`）。
- `src/config/index.js` 新增 `APP_TITLE` / `ENV_MODE` / `ENV_LABEL` / `IS_PROD` / `IS_DEV`，
  并接到首页与登录页标题、左上角**环境角标**（非生产才渲染）、H5 标签页标题（`uni.setNavigationBarTitle`，
  因为 `pages.json` 是静态 JSON 注入不了变量）。

### 修的真实缺陷
**`uni.login({provider:'weixin'})` 漏了 `#ifdef MP-WEIXIN` 守卫**（账号体系阶段遗留）。
只隐藏按钮拦不住编译：H5 与 App 产物里都带着微信原生登录调用，
而两端该 API 都不可用（H5 走微信网页授权需公众号 AppID；App 需开放平台资质 + manifest 配置）。
修复：用 `#ifdef` 包住原生调用，并改为「往外层变量赋值 + 统一判断」而不是块内 `return`
（uni-app 对 `#ifdef` 块内 `return` 处理不可靠）。

## 界面改版：首页改为微信式会话列表

### 背景

并要求「参考主流聊天程序」优化排版。确认方向为**改成微信式会话列表**。

### 新的信息架构
底部 TabBar 三项 + 品牌区迁移：
- **消息** `pages/index/index`（新建）：搜索框 + 会话列表 + ⊕ 新建对话
- **AI 助手** `pages/apps/apps`（新建）：品牌区（logo/标题/副标题）+ 两个 AI 入口 + 对话记录管理
- **我的** `pages/mine/mine`（新建）：账号卡片 / 连接（服务器地址·状态·存储）/ 数据 / 关于

**所有调试信息（后端地址、连接状态、编译默认地址、环境名）全部收进「我的」页，首页一条不留。**
原「对话历史」页与首页职责重叠，退化为「批量管理」工具，入口收进 AI 助手 / 我的。

### 关键交互（对齐主流习惯）
- 点会话行 → 进入对应 AI 续聊
- **长按会话行** → ActionSheet：继续对话 / 导出 PDF / 删除（替代原历史页每行挂 3 个按钮）
- ⊕ 悬浮按钮 → 选择 AI 主题 → 新建空白会话
- 时间显示四档：今天 `14:12` / 昨天 / 7 天内 `星期三` / 更早 `2026/9/16`

### 修的真实缺陷
**`ChatRoom` 传入不存在的 chatId 时会静默续上旧会话**。
原逻辑：`if (props.sessionId) { local查得到就恢复 }` → 查不到就落到「恢复本主题最近一次会话」。
后果有两个：
1. 首页点「新建对话」（传全新 id）→ 又续上了旧对话，功能形同失效；
2. 后端开了 MySQL、换设备后本地没有该会话 → 点开 A 会话却显示 B 的内容，**数据串号**。
修复：`loadSessionAsync`（远程优先，本地兜底）；传入 id 但查不到时**按该 id 开新会话**，
不再退回「恢复最近一次」。

## 第四轮：修「点击获取验证码报错」+ 备案号只在 H5 显示

### 「获取验证码」报错的真实根因（两层，都不在短信通道）
用户在小程序开发者工具里点「获取验证码」→ 404 + 前端提示「账号服务暂时不可用
（后端数据库未就绪）」。**这个提示把排查方向指错了**，实测根因是：

1. **本地 8000 端口跑的是旧版本后端进程**。
   决定性证据：`/api/health` 200、`/api/history` 200，但 `/api/auth/config` 与
   `/api/auth/sms/send` 全部 404；拉 `openapi.json` 一看，路由表里**一个 `/api/auth/*`
   都没有**。而源码 `app/main.py:104` 是无条件 `include_router(auth.router)` 的。
   → 进程比账号模块还老。`tasklist` 只有一个 python 进程（说明不是 reload 启动，
   所以改代码后一直没重新加载）。
   **排查手法（可复用）：用 `openapi.json` 的 paths 列表比对源码注册的路由，
   不要靠猜；再看 `tasklist` 进程数判断是否热重载启动。**
2. **`.env.dev` 里 `MYSQL_ENABLED=false`**。账号体系（验证码/用户/登录态）必须落库，
   这一项关着 → 所有 `/api/auth/*` 一律 503。与短信通道配置毫无关系。
   本机没装 MySQL（3306 未监听），故改为 sqlite：
   `MYSQL_ENABLED=true` + `MYSQL_HOST=sqlite:///./tmp/dev.db`。

> ⚠️ **uvicorn 热重载只监听 `.py`，不监听 `.env`**。改完 `.env*` 必须手动重启，
> 否则「改了配置没生效」会让人怀疑是代码问题。

### 前端：让错误提示对得上真实原因（避免下次再被误导）
- `api/http.js`：响应拦截器原先 `new Error(msg)` 把 **HTTP 状态码丢了**，导致
  404（后端没这个路由）与 503（后端在但没就绪）在页面上长得一模一样。
  现在把 `status` / `url` 挂到 error 上再抛。
- `pages/login/login.vue`：抽出 `markServiceDown(e)`，按状态码分流文案 ——
  404 → 「后端未部署账号服务（/api/auth 不存在，通常是后端版本过旧）」；
  503/未就绪 → 原提示。提示条文案改为动态 `serviceDownText`。

### 备案号：只有 H5 显示
用**模板条件编译** `<!-- #ifdef H5 -->` … `<!-- #endif -->` 整段剔除，
所以小程序 / App 产物里**根本没有这个节点**（不是 CSS 隐藏，也不是运行时不渲染）。
配套把 `beianText` / `onBeian` / `utils/beian` 的 import 也用 `// #ifdef H5` 包住。

**为什么不用「导出 SHOW_BEIAN 常量 + v-if」**（第一版写法，已改掉）：
运行时常量在压缩后变量名会消失，回归测试只能断言变量取值，非常脆弱；
条件编译在**构建期**就删掉节点，可以直接断言
「小程序 / App 产物不含『工信部备案查询』」——强得多。
