# H5 前端部署到百度智能云 · 宝塔面板

适用：本项目 `uniapp/` 的 H5 产物。**后端已经在微信云托管上跑**（域名
`https://yu-ai-agent-76469-5-1304297249.sh.run.tcloudbase.com`），
所以宝塔这台机器只需要放**静态文件**，不需要装 PHP / MySQL / Java / Python。

## 零、先确认这四件事，卡住 90% 的都在这一步

| # | 事项 | 说明 |
|---|---|---|
| 1 | **域名已备案且已"接入"百度智能云** | 域名解析到大陆服务器必须备案。若备案号（本项目 `闽ICP备2022001906号`）是在别家接入的，换到百度云需要在百度智能云备案系统做**「新增接入」**，审核要几天。没接入可能被拦截。 |
| 2 | **域名已解析到服务器公网 IP** | A 记录，`@` 和 `www` 各一条。改完等生效： `nslookup 你的域名` |
| 3 | **百度智能云安全组放行端口** | 控制台 → 云服务器 BCC → 安全组 → 入站放行 **80 / 443 / 22 / 8888**（宝塔面板）。默认往往只开 22/3389，**不放 80/443 网站永远打不开**。 |
| 4 | **宝塔防火墙也放行同样端口** | 宝塔面板 → 安全 → 放行 80/443/8888。两层都要开，只开一层照样不通。 |

> 项目里的备案号只在 H5 端展示（`#ifdef H5`），部署后记得在「我的」页底部确认显示了真实号码。

## 一、本机构建 H5 产物

### 1.1 确认后端地址（构建时会被**静态注入**，改了必须重新构建）

`uniapp/.env.production` 当前值：

```env
VITE_API_BASE_URL=https://yu-ai-agent-76469-5-1304297249.sh.run.tcloudbase.com/api
VITE_SSE_BASE_URL=https://yu-ai-agent-76469-5-1304297249.sh.run.tcloudbase.com/api
VITE_BEIAN_ICP=闽ICP备2022001906号
```

必须是 **https**：页面走 HTTPS 后，浏览器会拦截 http 接口（混合内容），
表现为"首页能开，但所有请求报 blocked:mixed-content"。

> 只想临时改后端地址、不想重新打包：App / H5 都能在「我的 → 服务器地址」里改，
> 存本地存储、运行时优先读。**但线上正式环境请写死在 `.env.production` 里**，
> 否则用户清一次缓存就回到默认地址。

### 1.2 构建

```bash
cd uniapp
npm run build:h5
```

产物目录：**`uniapp/dist/build/h5/`**（`index.html` + `assets/` + `static/`）

### 1.3 打包成压缩包（推荐，避免逐个文件传丢）

```bash
# Windows / macOS / Linux 都能跑（Windows 10+ 自带 tar）
tar -czf dist/love-master-h5.tar.gz -C dist/build/h5 .
```

或者：

```powershell
Compress-Archive -Path 'dist\build\h5\*' -DestinationPath 'dist\love-master-h5.zip' -Force
```

### ⚠️ 两个决定了"能不能部署成功"的产物特性

1. **产物里的资源路径是绝对路径**（`index.html` 里是 `/assets/index-xxx.js`，
   不是 `./assets/...`）。所以**必须部署到站点根目录**。
   想放子目录（如 `https://域名/love/`）就必须改 `vite.config.js` 加 `base: './'` 再重新构建，
   否则打开就是白屏 + 一堆 404。
2. **路由是 hash 模式**（`src/manifest.json` 里 `h5.router.mode = "hash"`），
   地址形如 `https://域名/#/pages/love/love`。
   → **不需要**配 Nginx 的 `try_files $uri $uri/ /index.html`。
   千万别照抄网上 Vue history 模式的教程，那套配置在 hash 模式下反而会出错。

## 二、宝塔建站

### 2.1 装环境

软件商店只装一个：**Nginx 1.22+**。
PHP、MySQL、phpMyAdmin、Tomcat **全都不用装**（后端在云托管）。

### 2.2 添加站点

网站 → 添加站点：

| 字段 | 填法 |
|---|---|
| 域名 | `你的域名` 和 `www.你的域名`（两行都填） |
| 根目录 | `/www/wwwroot/你的域名`（默认即可） |
| FTP | 不创建（用面板上传更安全） |
| 数据库 | 不创建 |
| PHP 版本 | **纯静态** |

### 2.3 上传产物

宝塔 → 文件 → 进 `/www/wwwroot/你的域名/`：

1. 删掉默认生成的 `index.html` / `404.html` / `.user.ini`
2. 上传 `love-master-h5.tar.gz` → 右键**解压** → 解压到当前目录
3. **确认目录结构是**：

```
/www/wwwroot/你的域名/
├── index.html          ← 必须在这一层，不能多套一层 h5/
├── assets/
└── static/
```

> 常见翻车：解压后变成 `/www/wwwroot/你的域名/h5/index.html`，
> 访问域名就是 403 目录列表。此时把 `h5/` 里的文件**剪切**到上一层。

## 三、Nginx 配置（站点 → 配置文件）

宝塔默认生成的配置不用大改，加下面几段即可（放在 `server {}` 内）：

```nginx
# ---------- gzip ----------
gzip on;
gzip_min_length 1k;
gzip_compress_level 6;
gzip_types text/plain text/css application/javascript application/json image/svg+xml;
gzip_vary on;

# ---------- 带 hash 的构建产物：可以长缓存 ----------
location ~* ^/assets/.*\.(js|css|woff2?|ttf|png|jpe?g|gif|svg|webp)$ {
    expires 30d;
    add_header Cache-Control "public, max-age=2592000, immutable";
    access_log off;
}

location ~* ^/static/ {
    expires 7d;
    access_log off;
}

# ---------- index.html 绝不缓存 ----------
# 不设的话，发新版后老用户打开还是旧页面（引用的是已被覆盖的旧 js），直接白屏。
location = /index.html {
    add_header Cache-Control "no-cache, must-revalidate";
    expires -1;
}
```

改完点保存，宝塔会自动重载 Nginx。

## 四、开启 HTTPS（必做）

站点 → SSL → Let's Encrypt → 选域名 → 申请 → 打开**强制 HTTPS**。

理由不只是安全：微信内置浏览器 / 部分安卓 WebView 对 http 站点会弹"不安全"，
而且后面的短信验证码接口在 http 下容易被运营商劫持。

## 六、故障对照表

| 现象 | 根因 | 处理 |
|---|---|---|
| 白屏，Network 里 `/assets/*.js` 全 404 | 部署到了子目录，而产物是绝对路径 | 移到站点根目录；或 `vite.config.js` 加 `base: './'` 重新构建 |
| 403 显示目录列表 | 多套了一层 `h5/` 目录 | 把文件剪切到上一层 |
| 刷新子页面 404 | 路由被改成 history 了 | `src/manifest.json` 里 `h5.router.mode` 必须是 `hash` |
| `blocked:mixed-content` | 页面 https，接口 http | `.env.production` 改 https 后**重新构建** |
| `Access-Control-Allow-Origin` 报错 | 后端没开 CORS 或没重启 | 后端 `cors_origins` 要含你的域名；云托管改环境变量后要**重新发布版本** |
| SSE 变成"一次性整段输出" | 走了反向代理且 `proxy_buffering` 没关 | 见下节 |
| 发新版后用户白屏 | `index.html` 被缓存 | 确认第三节的 `location = /index.html` 已加 |
| 域名打不开、超时 | 安全组/防火墙没放行 80/443 | 回第零节第 3、4 条 |

## 七、可选：用 Nginx 反向代理 `/api`（能隐藏后端地址）

不反代也能正常跑（后端 CORS 已开 `*`），反代只是可选优化。
**但 SSE 反代有个必踩的坑**，要做就把这段写全：

```nginx
location /api/ {
    proxy_pass https://yu-ai-agent-76469-5-1304297249.sh.run.tcloudbase.com/api/;
    proxy_set_header Host yu-ai-agent-76469-5-1304297249.sh.run.tcloudbase.com;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # ⚠️ SSE 三件套：少了第一条，流式回答会被 Nginx 攒到结束一次性吐出，
    #    表现为"AI 半天没反应，然后整段冒出来"。
    proxy_buffering off;
    proxy_cache off;
    proxy_http_version 1.1;
    chunked_transfer_encoding on;

    # AI 推理可能超过默认 60s
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

改反代后，`.env.production` 里 H5 的地址要改成相对路径再重新构建：

```env
VITE_API_BASE_URL=/api
VITE_SSE_BASE_URL=/api
```

⚠️ 这个 `.env.production` 只适合 **H5**。
小程序和 App **不能**用相对路径（没有同源概念），
所以别把这份配置拿去 `build:mp-weixin` / `build:app`，
否则打包出来的小程序和 App 全部请求失败。

## 八、后续更新怎么发版

```bash
cd uniapp
npm run build:h5
tar -czf dist/love-master-h5.tar.gz -C dist/build/h5 .
```

宝塔 → 文件 → 上传 → 覆盖解压 → **清一次浏览器缓存**（`index.html` 已设 no-cache，正常刷新即可）。

后端改了代码则要：微信云托管控制台 → 重新构建发布版本
（前端改了不用动后端，反之亦然，两边独立）。

> 注意：`.env.production` 里有 `VITE_` 变量是**构建时注入**的，
> 改完不重新构建就不会生效；而 `.dockerignore` 会排除 `.env.*`，
> 云端环境请一律在**云托管控制台的环境变量**里填，不要指望文件进容器。
