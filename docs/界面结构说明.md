# 界面结构说明（会话列表首页版）

> 改版动机：原首页是「应用入口卡片 + 调试信息条」，把后端地址
> `http://localhost:8000/api` 直接摊在用户面前，不像成品 App。
> 现改为主流聊天程序的结构 —— 首页即会话列表。

---

## 一、信息架构

```
底部 TabBar（3 个）
├── 消息   pages/index/index    会话列表 + 搜索 + 新建对话
├── AI 助手 pages/apps/apps      两个 AI 入口 + 对话记录管理 + 品牌区
└── 我的   pages/mine/mine      账号 / 连接 / 数据 / 关于

非 Tab 页（navigateTo 进入）
├── pages/love/love          AI 恋爱大师对话
├── pages/manus/manus        AI 超级智能体对话
├── pages/history/history    对话记录管理（批量导出 / 清空）
├── pages/login/login        登录 / 账号管理
└── pages/profile/profile    个人资料编辑（头像 / 昵称 / 签名）
```

**设计取舍**：原「对话历史」页与首页职责重叠（都是列会话），
所以首页接管了「浏览 + 进入 + 长按操作」，历史页退化为「批量管理」工具，
入口收进「AI 助手」和「我的」，不再占一级入口。

### 关键交互

| 操作 | 行为 | 对齐的主流习惯 |
|---|---|---|
| 点击会话行 | 进入对应 AI 页面继续该会话 | 微信点会话进入聊天 |
| **长按会话行** | 弹出操作菜单：继续对话 / 导出 PDF / 删除 | 微信长按会话弹操作菜单 |
| 点击右下角 ⊕ | 弹出选择「AI 恋爱大师 / AI 超级智能体」→ 新建空白会话 | Telegram / WhatsApp 的撰写按钮 |
| 顶部搜索框 | 按「标题 + 预览」实时过滤，带一键清空 | 微信顶部搜索 |
| 空态 | 「还没有对话」+「开始新对话」按钮 | —— |

**为什么操作收在长按里**：原历史页每行下面挂三个按钮（查看 / 导出 PDF / 删除），
一行占 3 倍高度且视觉很吵。长按菜单是聊天类 App 的通行做法，
日常浏览时列表干净，需要时才展开。

### 时间显示规则

| 距今 | 显示 |
|---|---|
| 今天 | `14:12` |
| 昨天 | `昨天` |
| 7 天内 | `星期三` |
| 更早 | `2026/9/16` |

## 三、AI 助手

品牌区（logo + 标题 + 副标题）放在这里而不是首页 —— 会话列表页要干净。

两个入口点击后**不传 chatId**，由对话页恢复该主题最近一次会话，
符合「点开助手就是接着上次聊」的习惯；想开新的去首页点 ⊕。

「对话记录管理」这一行顺带显示当前存储模式（云端 MySQL / 本机），
原来那条「后端未启用 MySQL，当前为本地存储」的提示条也收在这里。

### 常用话题（解决冷启动）

空输入框对用户是「冷启动」—— 不知道该问什么，于是干脆不问。
所以在两个 AI 入口下面按 AI 分块列了 10 条话题（`src/config/topics.js`）：

```
常用话题               点一下直接开问
┌────────────────────────────────┐
│ ❤ AI 恋爱大师                   │
│ 💔 我暗恋一个人很久了，但不知道… › │
│ 😶 我和对方吵架了，现在谁也不…  › │
├────────────────────────────────┤
│ 🤖 AI 超级智能体                │
│ 📅 帮我规划一次周末两天一夜的…  › │
└────────────────────────────────┘
```

点击后：跳对应 AI 页 → **开一条全新会话** → 把话题原句作为第一条消息发出去。

几点约定（都在代码注释里，这里给结论）：

- 话题文案必须是**完整可直接发送的句子**，不能是「关于异地恋」这种半截话 ——
  它会被直接当作用户消息发出去；
- 跳转只传 `topic=<id>`，不传中文全文（URL 里放中文要编解码，三端行为不一致）；
- 按 AI 分块展示：同一句话发给恋爱大师和发给超级智能体，回答完全不同，
  得让用户知道这句话会发给谁；
- 页面上话题文案超长会省略号截断，但**发出去的仍是完整原句**。

实现落在两处：`src/utils/topicEntry.js`（两个 AI 页共用的入口解析）
+ `ChatRoom` 的 `initialMessage` 属性（会话为空时自动 send）。

## 四、我的

| 分组 | 内容 |
|---|---|
| 账号卡片 | **头像 + 名称 + 账号**，右侧「编辑资料 ›」；未登录显示「去登录」 |
| 账号 | 账号与登录方式（显示已绑定方式数）、个人资料 |
| 数据 | 对话记录管理、清空全部对话 |
| 关于 | 应用名称、版本；**仅非生产构建**额外显示服务器地址（可点击修改）、连接状态、对话存储、运行环境、编译默认地址 |
| 底部 | **ICP 备案信息（居中）→ 点击跳工信部**，**仅 H5 展示**（见下） |

**所有排查用的信息（后端地址、连接状态、编译默认地址、环境名）都收在「关于」里，
且只在非生产构建出现。** 首页不再出现任何一条，生产包里一项都没有。

### 账号卡片

头像支持两种值，按前缀自动判别渲染方式：

- `http(s)://` 或 `data:` 开头 → 当图片渲染（留给将来接上传）；
- 其它 → 当文字渲染（emoji 或昵称首字符）。

**用 emoji 当内置头像而不是做图片上传**：三端零依赖、能随账号同步，
不需要图床 / 对象存储 / 上传接口。取首字符时用 `Array.from(n)[0]` 而不是 `n[0]` ——
后者遇到 emoji 会截出半个代理对，显示成乱码方块。

### 个人资料页（pages/profile/profile）

24 个内置 emoji 头像（再点同一项 = 取消选择）、昵称、账号（只读）、
性别 / 情感状态分段选择、生日用 `<picker mode="date">`、个性签名（60 字上限）。

字数统计用 `Array.from(x).length`，直接 `.length` 会把 emoji 算成 2 个。

对应后端 `User` 表的 4 个新字段（`gender` / `birthday` / `bio` / `emotion_status`）。

### 备案信息（ICP）

法规要求：境内运营的**网站**需在显著位置标注备案号并链接工信部备案系统。
配置走环境变量（`VITE_BEIAN_ICP` / `VITE_BEIAN_OWNER` / `VITE_BEIAN_POLICE`），
未配置时显示「备案号待配置」占位 —— 让界面照常可跑，但一眼能看出没填真号。

> **只有 H5 会展示备案号。** 实现方式是**模板条件编译**（`<!-- #ifdef H5 -->` …
> `<!-- #endif -->`）把整段节点剔除，所以小程序 / App 的产物里**根本没有这个节点**
> —— 不是靠 CSS 隐藏，也不是运行时不渲染。
>
> 为什么不给小程序 / App 展示：备案针对的是「境内网站」，H5 就是网页；
> 小程序与 App 走各自的主体资质审核流程，不在页面上展示备案号。
> 而且小程序内**没有任何接口能在应用内打开外部网页**（`web-view` 只加载
> 「自己配置过业务域名的页面」，工信部网址配不了），放上去只会得到一个点了
> 没反应的入口。
>
> 配套地，`mine.vue` 里 `beianText` / `onBeian` 与 `utils/beian` 的 import
> 也用 `// #ifdef H5` 包住，避免把用不到的跳转代码打进小程序 / App 包。
>
> 选条件编译而不是「导出个 `SHOW_BEIAN` 常量再 `v-if`」，是因为前者在**构建期**
> 就把节点去掉，产物里没有这段文案，回归测试可以直接断言
> 「小程序 / App 产物不含『工信部备案查询』」；用运行时布尔值则只能断言变量取值，
> 且变量名会被压缩，断言很脆弱。

`src/utils/beian.js` 按平台分派打开方式（App / 小程序分支保留备用，
当前只有 H5 会走到）：

| 平台 | 行为 |
|---|---|
| H5 | `window.open` 新标签页 |
| App | `plus.runtime.openURL` 交给系统浏览器（当前不展示入口，分支备用） |
| 小程序 | 复制链接 + 弹窗引导去浏览器粘贴（当前不展示入口，分支备用） |

上线前检查：`tmp/test_frontend_build.py` 第 8 节断言生产 H5 包内含真实备案号、
不残留哨兵值、渲染出备案入口；第 11 节断言**小程序与 App 产物不含备案入口**。

## 五、开发约定

### 1. Tab 页只能用 switchTab 跳转

对 tabBar 页面用 `navigateTo` 在微信小程序会**静默失败**，很难排查。
所以收口到 `src/config/index.js` 的 `goPage(path)`：

```js
import { goPage, PAGE } from '@/config'
goPage(PAGE.mine)   // 自动判断 tab 页走 switchTab、普通页走 navigateTo
```

### 2. 新增页面记得改三处

1. `src/pages.json` 的 `pages` 数组
2. `src/config/index.js` 的 `PAGE` 常量
3. 小程序端如果 `navigateTo` 报 "page is not found"，在开发者工具点一次「编译」
   （wxml/js 会热更新，但 app.json 的页面注册表可能还是旧的）

### 3. 平台专有代码必须包 `#ifdef`

只隐藏按钮拦不住编译 —— 代码照样会进所有端的产物。
（踩过的坑：`uni.login({provider:'weixin'})` 漏了守卫，
结果 H5 / App 产物里都带着微信登录逻辑。）

### 4. 涉及 `position: fixed` 的元素要自己让开 tabBar

`fixed` 是相对视口定位的，H5 下会被 tabBar 压住，要用
`calc(48rpx + var(--window-bottom, 0px))` 且只在 `#ifdef H5` 里写
（MP / App 下 `--window-bottom` 不存在，写进去有兼容风险）。

## 六、TabBar 图标

`uniapp/src/static/tabbar/` 下 6 张 PNG（81×81，未选中灰 `#9aa0a6` / 选中粉 `#ff4d6d`）。

**用脚本生成而不是找现成图标库**（`tmp/gen_tabbar_icons.py`）：

- 微信小程序 tabBar 只认 PNG/JPG，不认 SVG，单张必须 < 40KB（当前都在 3KB 左右）；
- 自己画能保证三个图标的线宽、留白、视觉重量一致 —— 图标库里凑的三套往往粗细不一，
  放在一行里很明显。

改图标只要改脚本里的绘制函数再重跑。

## 八、对话导出的入口

导出 PDF 的逻辑**没有删**，被抽成了共享模块 `src/utils/exportPdf.js`：

```js
exportSessionPdf(item)        // 按会话导出（会自动补全消息、调后端 /ai/chat/export-pdf）
formatChatTime(stamp)         // 四档时间显示（首页 / 历史页共用）
```

改版的只是**入口位置**：

| 入口 | 用法 |
|---|---|
| 首页长按会话行 → 「导出 PDF」 | 单个会话导出，主入口 |
| 我的 → 对话记录管理 → 每行的导出按钮 | 批量管理场景 |
| AI 助手 → 对话记录管理 | 同上（同一个页面） |

为什么从「每行一个按钮」改成「长按菜单」：原来一行挂三个按钮，
行高是现在的 3 倍、视觉很吵；长按菜单是聊天类 App 的通行做法。
