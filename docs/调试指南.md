# 断点调试与日志调试指南

> 适用：恋爱大师（Python 3.12 + FastAPI + LangChain / LangGraph）
> IDE：PyCharm 2024.1 / VS Code

---

## 一、先解决断点不生效的问题（最关键）

### 根因

`main.py` 原本的启动方式是：

```python
uvicorn.run("app.main:app", reload=settings.debug, ...)
```

而 `settings.debug` 默认为 `True`（见 `app/config/settings.py`），于是 **uvicorn 会开启热重载**。

热重载的工作方式是「父进程监控文件 + 子进程跑真正的应用」：

```
python main.py
  └── 父进程（reloader，只负责监听文件变化）
        └── 子进程（真正运行 FastAPI 应用）  ← 你的断点在这里
```

调试器默认只附着**父进程**，所以断点要么不命中，要么命中了也是空壳。此外任何文件保存都会重启子进程，调试会话直接作废。

### 解决方式

`main.py` 已支持用环境变量覆盖热重载开关：

```bash
RELOAD=false python main.py
```

优先级：`RELOAD` 环境变量 > `.env` 中的 `DEBUG`。不设置 `RELOAD` 时行为与改造前完全一致。

> 不建议用 `DEBUG=false` 来关热重载 —— 那会顺带把日志级别从 DEBUG 降到 INFO，反而看不到调试信息。

## 二、PyCharm 配置

`Run` → `Edit Configurations...` → `+` → `Python`

### 配置 A：用 uvicorn 模块启动（推荐）

| 字段 | 值 |
|---|---|
| Name | `恋爱大师-调试` |
| 运行方式 | 选 **Module name**（不是 Script path） |
| Module name | `uvicorn` |
| Parameters | `app.main:app --host 127.0.0.1 --port 8000 --log-level debug` |
| Working directory | 项目根目录 |
| Python interpreter | 项目 `.venv` |
| Environment variables | `RELOAD=false;LLM_DEBUG=true` |

勾选 `Add content roots to PYTHONPATH` 与 `Add source roots to PYTHONPATH`。

这种方式完全绕过 `main.py` 里的 `reload` 参数，最干净。

### 配置 B：直接跑 main.py

| 字段 | 值 |
|---|---|
| Name | `恋爱大师-main` |
| 运行方式 | **Script path** |
| Script path | `<项目根>/main.py` |
| Working directory | 项目根目录 |
| Environment variables | `RELOAD=false;LLM_DEBUG=true` |

### 让调试器能步入第三方库

PyCharm 默认开启 `Just my code`，会跳过 `site-packages` 里的代码。
想单步进 LangChain 内部时：

`Settings` → `Build, Execution, Deployment` → `Debugger` → `Python Debugger` → 取消勾选 **Just my code**。

## 三、VS Code 配置

已生成 `.vscode/launch.json`，包含 5 个配置：

| 配置名 | 用途 |
|---|---|
| 调试服务（关热重载 + LLM 详细日志） | 主用，uvicorn 启动，`RELOAD=false` + `LLM_DEBUG=true` |
| 调试 main.py（关热重载） | 从 `main.py` 启动 |
| 调试当前测试文件（-s 直出控制台） | 调试单元测试，`-s` 让输出不被 pytest 捕获 |
| 调试当前文件 | 通用脚本调试 |
| 附加到本地进程 | attach 模式，见下文 |

所有配置都设了 `"justMyCode": false`，可步入第三方库。

> 若提示 `type "debugpy" 无法识别`，说明 Python 扩展过旧，把 `"type": "debugpy"` 改成 `"type": "python"` 即可。

### attach 模式（调试已运行的进程）

```bash
# 1. 装 debugpy（可选依赖组里没有，单独装）
.venv\Scripts\python.exe -m pip install debugpy

# 2. 带调试端口启动服务
.venv\Scripts\python.exe -m debugpy --listen 5678 --wait-for-client main.py

# 3. VS Code 里选「附加到本地进程（需先启动 debugpy）」
#    PyCharm 里用 Run → Attach to Process
```

`--wait-for-client` 会让服务暂停等待调试器接入，适合调试启动阶段的代码（如 `lifespan`、路由注册）。

## 四、控制台打印调试内容

### 1. 业务日志（默认已可用）

`app/utils/logger.py` 的 `setup_logging()` 会在 `DEBUG=true` 时把全局级别设为 DEBUG，格式：

```
2026-09-21 22:10:33 | INFO    | app.app.love_app | 对话完成 session=user_001
```

代码里直接用：

```python
from app.utils import get_logger

logger = get_logger(__name__)

logger.debug("history 条数=%d, 内容=%s", len(history), history)
logger.info("对话完成 session=%s", self.session_id)
logger.warning("降级处理：%s", exc)
```

> 现状提醒：项目代码目前几乎只打 `logger.info`，`logger.debug` 基本没铺开。
> 所以「DEBUG 级别已开」但看不到多少调试输出——这是正常的，需要时自己加 `logger.debug`。

### 2. 看大模型实际收到的 Prompt（调试 AI 应用最有用）

用 `LLM_DEBUG=true` 开启，会打印每次调用的完整 messages（system / 历史 / 本轮输入）：

```bash
LLM_DEBUG=true python main.py
```

或在 IDE 配置的 Environment variables 里加 `LLM_DEBUG=true`。

实现位于 `app/utils/logger.py` 的 `enable_llm_debug()`：

```python
def enable_llm_debug() -> None:
    from langchain_core.globals import set_verbose
    set_verbose(True)
    for name in ("httpx", "httpcore"):
        logging.getLogger(name).setLevel(logging.INFO)
```

> ⚠️ 踩坑提示：`langchain-core 0.3.29` 的 `globals.py` **不读环境变量**，
> 网上常见的 `LANGCHAIN_VERBOSE=true` 在这个版本上不生效，必须走 `set_verbose()` 代码 API。
> 这也是这里没有直接用环境变量的原因。

也可以在代码里随时手动开关：

```python
from app.utils import enable_llm_debug
enable_llm_debug()
```

### 3. 临时 print

- 直接运行时：`print()` 会输出到终端。
- **pytest 里必须加 `-s`**，否则 pytest 会捕获 stdout，`print` 不显示：

```bash
.venv\Scripts\python.exe -m pytest tests/test_chat_memory.py -s -v
```

对应的 VS Code 配置已内置 `-s`。

## 六、常见问题

**Q：断点显示为灰色空心圆圈（未绑定）？**
A：多半是热重载没关，或断点所在文件与运行的代码不是同一份。先确认 `RELOAD=false`。

**Q：改了代码不重启也能生效吗？**
A：常规运行下可以（`reload=True`）。调试时必须牺牲热重载，改完代码手动重启调试会话。

**Q：`LLM_DEBUG=true` 了但没看到 Prompt？**
A：确认该环境变量真的传给了进程。PowerShell 里临时设置用 `$env:LLM_DEBUG="true"`，
CMD 用 `set LLM_DEBUG=true`，Git Bash 用 `export LLM_DEBUG=true`。
另外服务必须在设置之后再启动（`setup_logging()` 只在启动时读一次）。

**Q：控制台被 httpx 日志刷屏？**
A：说明开了 HTTP 层日志（`enable_llm_debug` 会放开 httpx/httpcore）。
不想要就单独把那两行 `setLevel(logging.INFO)` 去掉，仅保留 `set_verbose(True)`。
