# 部署到微信云托管

把「恋爱大师」后端（Python 3.12 + FastAPI）部署到微信云托管，前端三端改成访问云上域名。

## 一、部署前后对比

| 项 | 本地开发 | 微信云托管 |
|---|---|---|
| 运行方式 | `python main.py`（uvicorn） | 容器实例（按 Dockerfile 构建） |
| 监听端口 | `8000` | **`80`**（由控制台「新建版本」时填写） |
| 配置来源 | 项目根目录 `.env` | **控制台环境变量**（镜像里不含任何密钥） |
| 数据库 | 本机 PostgreSQL + pgvector | 建议**不用**，RAG 走阿里云百炼知识库 |
| 访问地址 | `http://localhost:8000` | `https://<服务名>.app.tcloudbase.com` |

## 二、代码里已经做好的改造

| 文件 | 改动 |
|---|---|
| `Dockerfile` | 端口改为 `${PORT}` 动态展开（默认 80）；去掉 `build-essential`（依赖均有预编译轮子，镜像更小）；补 `HEALTHCHECK`；只挑装 `requests` / `reportlab` / `chardet`，不装 playwright / ollama |
| `.dockerignore` | **新建**。排除 `.env` / `*.csv` / `*.key`（防密钥泄露）、`.venv`、`uniapp/`、`docs/`、`tests/`、`data/postgres/` |
| `.env.cloudrun.example` | **新建**。云上环境变量清单（不含真实密钥，可提交 Git） |
| `uniapp/.env.production` | 后端地址改为云托管 https 域名占位符 |

> 关于依赖取舍：`requests` 是 `app/tools/love_tools.py` 的**模块级硬依赖**，必须装；
> `reportlab` 用于恋爱报告 PDF（函数内软依赖）；`playwright` 在代码里 0 处引用且自带浏览器内核体积巨大，云上不装；
> Ollama 本地模型在云托管跑不动，且 `get_ollama_chat_model()` 是函数内软依赖，不装也不影响启动。

## 三、部署步骤

### 前置条件

1. 微信云托管服务已开通（微信公众平台 / 小程序后台 → 云托管）
2. **强烈建议先在本地 Docker 跑通**再上云（官方要求）。本机目前未安装 Docker，
   若本地无法验证，就直接在云托管构建，遇到构建失败看控制台构建日志定位。

### 方式 A：绑定 Git 仓库（推荐）

把项目推到 GitHub / GitLab / Gitee，云托管会自动拉取并构建：

1. 云托管控制台 → 新建服务 → 选择代码来源「绑定 Git 仓库」
2. 授权并选中仓库、分支
3. **端口填 `80`**（与 Dockerfile 的 `ENV PORT=80` 一致）
4. 构建目录留空（Dockerfile 在根目录）
5. Dockerfile 路径填 `Dockerfile`
6. 填环境变量（见下一节）
7. 点发布，观察构建日志

> 优点：不受 2 MiB 代码包限制，后续 push 可直接触发流水线。

### 方式 B：手动上传代码包

1. 先把项目里不需要的文件删掉，或确保 `.dockerignore` 生效
2. 打包为 zip（**≤ 2 MiB**）
3. 云托管控制台 → 新建版本 →「手动上传代码包」
4. 端口填 `80`，Dockerfile 路径填 `Dockerfile`
5. 填环境变量 → 发布

> 当前构建上下文经校验为 **0.16 MiB**（48 个文件），远低于上限，可以走这条路。
> 校验方法：`python tmp/check_docker_context.py`

## 四、环境变量配置

控制台 → **服务设置 → 基本信息 → 环境变量**。

### 4.1 「配完再打开还是空」——先看清编辑器顶部的 JSON 开关

环境变量编辑器右上角有个 **「JSON」开关**，两种模式互斥：

| 模式 | 该填什么 | 填错了会怎样 |
| --- | --- | --- |
| **JSON 关闭**（默认，表单/键值对模式） | 点「添加」逐行填 `键` / `值` | — |
| **JSON 打开** | 只能填 JSON：见 4.2 | 填 `KEY=VALUE` 行式 → 解析失败 → 保存静默失败 → **再打开就是空的** |

> 截图里 JSON 开关是**亮着的**，但你填的是 `KEY=VALUE` 行式，所以存不进去。
> **最省事的做法：把 JSON 开关关掉，用表单逐条添加**（100% 不会踩格式坑）。

即使格式填对了，还有两个高频坑：

1. **没点保存**——环境变量面板要拉到**最底部**才有「保存 / 确定」按钮，直接关弹层等于没配。
2. **改完没重新发布版本**——面板里有值也不生效，必须去「版本管理」重新发布。

### 4.2 想用 JSON 模式？直接复制生成好的内容

```bash
python tmp/gen_cloudrun_env.py
```

会生成三份（**含真实密钥，配完记得删**）：

| 文件 | 格式 | 用在哪 |
| --- | --- | --- |
| `tmp/cloudrun_env.json` | `{"KEY": "VALUE", ...}` | JSON 模式首选 |
| `tmp/cloudrun_env_array.json` | `[{"name":"KEY","value":"VALUE"}, ...]` | 对象格式报格式错误时试这个 |
| `tmp/cloudrun_env.txt` | `KEY=VALUE` 行式 | 表单模式照着填 / CI 用 |

粘贴时**整段替换**输入框里的内容，不要追加；末尾不要留逗号，不要带注释。

### 4.3 已知坑

> ⚠️ **首次部署成功后环境变量会消失**，需要在服务设置里**重新补全**，
> 且**改完要重新发布版本**才会生效（官方服务市场已确认该现象）。
>
> 快速判断有没有生效：访问 `/api/health`，看返回的 `env` 字段 ——
> 若仍是 `dev`（而非你配的 `prod`），说明一个环境变量都没注入成功。

> ⚠️ **别把本地 `.env` 原样搬上去**：里面 `PORT=8000`、`DEBUG=true`、`APP_ENV=dev` 都是开发值，
> 端口不对会直接部署失败，`DEBUG=true` 会让 uvicorn 开热重载 fork 子进程。
> 云上必须改成 `PORT=80`、`DEBUG=false`、`APP_ENV=prod`。

**最小可用集**（只填这些就能跑通对话）：

```
PORT=80
DEBUG=false
CORS_ORIGINS=["*"]
DASHSCOPE_API_KEY=sk-你的真实key
DASHSCOPE_CHAT_MODEL=qwen-plus
RAG_BACKEND=bailian
BAILIAN_WORKSPACE_ID=llm-xxxxxxxxxxxx
BAILIAN_INDEX_ID=你的知识库ID
```

### 4.4 账号 / 短信 / 数据库（要登录就必须补）

**关键前提：`.env.prod` 里的值不会进容器。** `.dockerignore` 排除了 `.env.*`
（这是对的——密钥不能进镜像），所以**在 `.env.prod` 里填的值只对"本地以生产模式自测"有效**，
云上必须逐项填进控制台环境变量。`.env.prod` 只是一份"该配什么"的对照清单。

> 实测踩过：`.env.prod` 里 `ALIYUN_SMS_SIGN_NAME` / `ALIYUN_SMS_TEMPLATE_CODE` 都填了，
> 结果 App 上发验证码报「阿里云短信认证配置不完整」——
> 因为那两个值在文件里、没在控制台。**别看文件，看 `/api/health/config` 的 `smsMissing`。**

```
# ---- 开关（非密钥，可写 .env.prod，但云上仍要填控制台）----
AUTH_ENABLED=true
SMS_PROVIDER=aliyun_pnvs          # aliyun_pnvs=个人可用 / aliyun=企业 / tencent
ALIYUN_SMS_SIGN_NAME=速通互联验证码   # 【签名配置】页签的品牌名，不是模板名称！
ALIYUN_SMS_TEMPLATE_CODE=100001    # 【模板配置】页签的 Code（数字）
ALIYUN_SMS_CODE_PARAM=code
ALIYUN_SMS_REGION=cn-hangzhou

# ---- 密钥（只放控制台，绝不写 .env.prod）----
ALIYUN_ACCESS_KEY_ID=LTAI...
ALIYUN_ACCESS_KEY_SECRET=...
JWT_SECRET=<python -c "import secrets;print(secrets.token_hex(32))" 生成>

# ---- 数据库（微信云托管自建 MySQL，用内网地址）----
MYSQL_ENABLED=true
MYSQL_HOST=<实例详情里的内网地址>
MYSQL_PORT=3306
MYSQL_DATABASE=love_master
MYSQL_USER=<用户名>
MYSQL_PASSWORD=<密码>
MYSQL_CHARSET=utf8mb4
MYSQL_POOL_SIZE=5
MYSQL_POOL_RECYCLE=280
```

**配完必验**（缺哪项它会直接把变量名列出来，不用猜）：

```bash
curl https://<你的云托管域名>/api/health/config
# 看 smsReady 应为 true、smsMissing 应为 []
```

> ⚠️ `ALIYUN_SMS_SIGN_NAME` 填错是高频错误：它必须是【签名配置】页签里的
> **品牌签名**（如 `速通互联验证码`），不是【模板配置】页签里的模板名称
> （如 `登录/注册模板`、`验证绑定手机号模板`）。填错只会在真发短信时报
> `isv.SMS_SIGNATURE_ILLEGAL`，跟"配置不完整"是两种完全不同的错。

### 关于 RAG：为什么推荐 `bailian` 而不是 `local`

- `local` 依赖 PostgreSQL 的 **pgvector** 扩展。微信生态的 PostgreSQL 是否开放 pgvector
  **因版本和地域而异**，需在控制台「数据库 → 扩展管理」确认；不支持的话向量库直接不可用。
- `bailian` 直接复用你在阿里云百炼控制台已配好的知识库，**云托管侧零数据库依赖**，
  部署最省事，也不用管数据持久化（云托管容器文件系统重启即丢）。
- 代码已有兜底：`rag_mode` 在 bailian 参数不全时会**自动回退 local**，
  所以就算 `BAILIAN_*` 少填了也不会整个 RAG 链路挂掉（前提是有可用的 pgvector）。

## 五、前端配置

部署成功后，云托管会给一个公网域名（形如 `https://<服务名>-<环境ID>.<地域>.app.tcloudbase.com`）。

1. 改 `uniapp/.env.production`，把两行 `REPLACE-WITH-YOUR-DOMAIN` 换成真实域名：
   ```ini
   VITE_API_BASE_URL=https://你的域名/api
   VITE_SSE_BASE_URL=https://你的域名/api
   ```
2. 重新构建各端产物：
   ```bash
   npm run build:h5
   npm run build:mp-weixin
   npm run build:app
   ```
3. **微信小程序**还需在公众平台「开发管理 → 开发设置 → 服务器域名」把该域名加进
   request 合法域名，否则真机请求被拦。
4. **App**：`usesCleartextTraffic` 可保留（https 不受影响）；域名变了不想重新打包的话，
   在「我的 → 服务器地址」里运行时改即可。

部署完成后按顺序检查：

curl https://你的域名/api/health          # 应返回健康状态
curl https://你的域名/                    # 服务概览
curl https://你的域名/docs                # Swagger UI（静态资源已自托管，国内直连可用）

## 七、常见问题

**Q1：部署后容器一直起不来 / 健康检查失败？**
- 先确认**控制台填的端口**和 Dockerfile 的 `PORT` 一致（都是 80）
- 首次启动要导入 LangChain 全家桶，较慢。`HEALTHCHECK` 已给 90s `start-period`，
  若云托管的健康检查超时更短，可适当调高「容器规格」或精简依赖
- 看云托管控制台的**构建日志**和**运行日志**定位

**Q2：`DEBUG` 忘了关会怎样？**
`main.py` 里 `DEBUG=true` 会让 uvicorn 开启 `--reload`，它会 fork 子进程，
在容器里容易引发启动异常和端口占用。**线上务必 `DEBUG=false`**。

**Q3：最小实例数设成 0 会不会有问题？**
功能上没问题（云托管会在首次请求时冷启动），但本项目冷启动较慢
（LangChain + LangGraph 导入）。若在意首包延迟，把最小实例数设为 1。

**Q4：接口被别人白嫖怎么办？**
开启 `API_KEY_ENABLED=true` 并配置 `API_KEYS`（英文逗号分隔），
前端请求带上 `Authorization: Bearer <key>`。注意这是**简易鉴权**，不是生产级方案。

**Q5：PDF 恋爱报告功能能用吗？**
能。`reportlab` 已在镜像里装好。但注意云托管容器**文件系统不持久化**，
生成的 PDF 存在 `/app/tmp/pdf`，容器重启后会丢失；需要长期保存就接对象存储。

**Q6：`/api/health` 返回 `llm_ready: false`、`env: "dev"` 怎么解决？**
说明**环境变量一个都没注入**。按这个顺序处理：

1. 服务设置 → 基本信息 → 环境变量，逐条补上（见第四节）
2. **改完必须重新发布版本**，仅保存不会生效
3. 重新访问 `/api/health`，应变为 `llm_ready: true`、`env: "prod"`

> 别把本地 `.env` 原样搬上去：`PORT` 必须是 80、`DEBUG` 必须是 false。
> 想省事可以用 `python tmp/gen_cloudrun_env.py` 生成一份已按云上要求修正过的清单
> （输出到 `tmp/cloudrun_env.txt`，含真实 Key，已确认 `tmp/` 在 `.gitignore` 中）。

**Q7：配好 Key 后对话正常，但「RAG 问答」/「恋爱报告」报错？**
这是预期内的——这两条链路才依赖知识库：

| 功能 | 是否依赖 RAG / 数据库 |
|---|---|
| AI 恋爱大师的 SSE 流式对话（`chat_stream`） | ❌ 不依赖，配好 DashScope Key 即可用 |
| RAG 增强问答（`chat_with_rag`） | ✅ 依赖 |
| 恋爱报告 PDF（`generate_report`） | ✅ 依赖 |

解决方式二选一：
- 用阿里云百炼知识库：配 `RAG_BACKEND=bailian` + `BAILIAN_WORKSPACE_ID` + `BAILIAN_INDEX_ID`
- 用自建向量库：在云托管开通 PostgreSQL 并确认 pgvector 扩展可用，配 `PGVECTOR_*`

**Q8：浏览器打开 `/docs` 是空白页，或者接口文档打不开？**

两件事先分清——**文档地址不带 `/api` 前缀**：

| 地址 | 结果 |
|---|---|
| `https://你的域名/docs` | ✅ Swagger UI |
| `https://你的域名/openapi.json` | ✅ 原始 OpenAPI 描述（文档页靠它渲染） |
| `https://你的域名/api/docs` | ❌ 404（`/api` 是业务接口前缀，文档不在其下） |
| `https://你的域名/redoc` | ❌ 已停用（它同样依赖国外 CDN） |

如果地址对了还是**白屏**：FastAPI 默认从 `cdn.jsdelivr.net` 加载 Swagger UI 的
JS/CSS（约 1.4MB），国内网络经常加载不出来。本项目已改为**自托管**：

- 静态资源在 `app/static/docs/`（swagger-ui-bundle.js + swagger-ui.css，取自
  swagger-ui-dist@5.33.0，经 npmmirror 下载）
- `main.py` 里 `docs_url=None, redoc_url=None` 关掉默认路由，用
  `get_swagger_ui_html()` 自建 `/docs`，JS/CSS 指向镜像内 `/static/docs/`
- 已实测：`/docs` 页面引用的资源全部来自本服务，不再有第三方 CDN 依赖

**改动生效需要重新上传代码包并发布新版本**（旧镜像里没有这些静态文件）。
更新 `.dockerignore` 后构建上下文 49 个文件、未压缩 1.85 MiB、zip 后约 0.51 MiB，在限额内。

**Q9：容器重启后对话历史没了怎么办？**
这是预期行为——云托管容器**文件系统不持久**，所以历史记录要存数据库。
项目已支持 MySQL 持久化，见第八节。

## 八、对话历史存储（MySQL）

### 8.1 为什么需要
对话历史原本存在用户设备本地（`uni.setStorageSync`），存在两个问题：
容器重启 / 换设备 / 换端（H5 与 App 之间）都看不到历史。落库后可跨端共享。

### 8.2 控制台开通步骤
1. 云托管控制台 → 左侧「**数据库**」→ 选 MySQL → 新建实例（与服务在**同一环境**）
2. 建好后进入实例详情，记下**内网**连接信息：主机名、端口、数据库名、账号、密码
3. 服务设置 → 环境变量，补上（同 `.env.cloudrun.example` 第七节）：

```
MYSQL_ENABLED=true
MYSQL_HOST=<内网主机地址>
MYSQL_PORT=3306
MYSQL_DATABASE=love_master
MYSQL_USER=<用户名>
MYSQL_PASSWORD=<密码>
MYSQL_CHARSET=utf8mb4
MYSQL_POOL_SIZE=5
MYSQL_POOL_RECYCLE=280
```

4. **重新发布版本**生效

> ⚠️ 必须用**内网**地址：同一环境内服务与数据库内网互通，走公网会有延迟和额外费用，
> 且需要数据库开公网访问（不安全）。

### 8.3 表结构与建表
首次启动自动建表（`Base.metadata.create_all`），无需手工执行 DDL：

| 表 | 主要字段 |
|---|---|
| `chat_session` | id(PK)、user_id、title、theme、created_at、updated_at |
| `chat_message` | id(自增 PK)、session_id(FK)、seq、role、content(TEXT)、time_label、created_at |

字符集 `utf8mb4`（支持 emoji），引擎 InnoDB。

### 8.4 接口
前缀 `/api/history`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 列表（支持 theme / limit / offset） |
| GET | `/{session_id}` | 详情（含 messages） |
| PUT | `/{session_id}` | 整段保存（幂等 upsert） |
| DELETE | `/{session_id}` | 删除 |
| DELETE | `/` | 清空 |
| POST | `/{session_id}/export-pdf` | 按库里的数据导出 PDF（前端无需回传全文） |

### 8.5 降级设计（重要）
`MYSQL_ENABLED=false` 或连不上数据库时：
- 后端启动**不受影响**，只记录日志
- 读接口返回 `{"available": false, ...}`，写接口返回 503
- 前端自动回退本地存储，历史页顶部显示「后端未启用 MySQL，当前为本地存储」

所以本地开发（没装 MySQL）也能正常使用，只是历史不跨设备。

### 8.6 本地自测（无 MySQL 时）
用 SQLite 验证数据层逻辑（SQLAlchemy 通用，仅驱动不同）：

```bash
MYSQL_ENABLED=true \
MYSQL_HOST="sqlite:///C:/Users/27957/Desktop/恋爱大师/tmp/test_history.db" \
python main.py
```

再调 `PUT /api/history/t1`、`GET /api/history`、`POST /api/history/t1/export-pdf` 验证。
（生产环境不要这样配，SQLite 仅用于本地验证表结构与接口。）

### 8.7 鉴权提醒
若把 `API_KEY_ENABLED` 打开，`/api/history` 属于 `/api/*` 会被鉴权拦截，
而前端当前没有携带 `X-API-Key`。二选一：
- 保持鉴权关闭；
- 或把 `/api/history` 加进 `app/core/middleware.py` 的 `_PUBLIC_PREFIXES`；
- 或在前端请求头统一带上 Key。

## 九、「本地已经修好，线上（App）还是报错」——发布检查清单

这是踩得最狠的一类问题：**环境变量改了、代码没发布**，或者**代码发布了、环境变量没改**。
两边必须同时到位才会生效，缺任何一边都会看到「还是报错」。

### 9.1 三步定位：先分清是「代码旧」还是「配置错」

**第 1 步 —— 看线上配置体检（判断环境变量）**

```bash
curl https://你的域名/api/health/config
```

对照下表：

| 字段 | 期望值 | 不对怎么办 |
|---|---|---|
| `sms` | `aliyun_pnvs` | 改控制台 `SMS_PROVIDER` |
| `smsReady` | `true` | 看 `smsMissing` 数组里缺什么 |
| `smsMissing` | `[]` | 缺哪个补哪个 |
| `smsSignName` | `北京恒创联众` | 必须与阿里云控制台「短信认证参数管理」逐字一致 |
| `smsTemplateCode` | `100001` | 是模板 **CODE**，不是模板名称 |
| `smsRealSend` | `true` | 为 `false` 说明还在 `SMS_DEV_MODE` |
| `smsDevCodeExposed` | `false` | 生产必须为 false，否则任何人都能拿到别人的验证码 |

**第 2 步 —— 看有没有 `smsRealSend` 字段（判断代码新旧）⚡ 最快**

这个字段是某次修复时才加进 `config_summary` 的。用它当「版本号探测器」：

| 线上 `/api/health/config` 返回 | 结论 |
|---|---|
| **没有** `smsRealSend` 键 | ❌ 线上是**旧代码**，本地再怎么改都不会生效 → 去 9.2 发布 |
| **有** `smsRealSend` 且为 `true` | ✅ 线上是新代码，还报错就去 9.3 按错误码判读 |

**第 3 步 —— 直接打线上发送接口（拿到真实错误码）**

```bash
curl -X POST https://你的域名/api/auth/sms/send \
  -H "Content-Type: application/json" \
  -d '{"phone":"你的手机号"}'
```

返回体里会带上阿里云原始错误码 + 处理建议，比 App 截图清楚得多
（App 端 toast 会截断，长文案只在页面横幅里完整显示）。

### 9.2 发布：代码 + 环境变量必须同时到位

**方式 A：绑定 Git 仓库**

1. 本地 `git commit` + `git push`（确认改动已提交，**工作区未提交的改动不会进构建**）
2. 云托管控制台 → 服务 → 部署 → 选择最新提交 → 构建并发布
3. 构建日志出现 `Successfully built` 后再点**发布**

**方式 B：手动上传代码包**

1. 打包时**排除** `.venv/`、`uniapp/`、`data/`、`tmp/`、`.env*`（`.dockerignore` 已配好）
2. 整包 ≤ 2 MiB，超过就走方式 A
3. 上传 → 构建 → **发布**

> ⚠️ 最容易漏的一步：**改完环境变量必须「重新发布版本」**，只点保存不会生效。
> 服务设置 → 环境变量 → 保存 → 回到「版本管理」→ 点**发布**。

### 9.3 发布后验证

```bash
# 1. 新代码已上：返回里应出现 smsRealSend
curl https://你的域名/api/health/config | grep smsRealSend

# 2. 真发一条
curl -X POST https://你的域名/api/auth/sms/send \
  -H "Content-Type: application/json" -d '{"phone":"你的手机号"}'
# 期望：{"ok":true,"phone":"159****7681","expiresIn":300,"resendAfter":60}
```

### 9.4 还报错？按错误码判读

| 阿里云错误码 | 含义 | 处理 |
|---|---|---|
| `Code=OK` / `ok` | ✅ 成功 | — |
| `isv.INVALID_PARAMETERS: 签名或者模版无效` | 签名/模板不是本账号的 | 核对 `smsSignName`/`smsTemplateCode`（见 9.1）；签名名库里多个主体都显示"已通过"，**只有同主体的能实际下发** |
| `isv.INVALID_PARAMETERS: 请检查模板内容与模板参数是否匹配` | TemplateParam 问题 | 若是旧代码（`##code##` 占位符被拒）→ 升级到服务端直接传验证码的版本 |
| `ILLEGAL_MOBILE` | 手机号不合法 | **好消息**：说明签名/模板校验已通过，换真实号码即可 |
| `biz.FREQUENCY` / `600016` | 限流 | 同号码 1 条/分钟、5 条/小时、10 条/天；等窗口或加白名单 |
| `MissingTemplateParam` | 模板变量没传齐 | 赠送模板 100001 有 `$code$` + `$min$` 两个变量，必须都传 |

### 9.5 两个反直觉的坑

1. **阿里云门户「调试成功」≠ 后端能发。**
   门户调试用的是你手填的参数，后端用的是环境变量。两边不一致时门户永远成功。
   用 `/api/health/config` 的 `smsSignName`/`smsTemplateCode` 与门户调试参数**逐字比对**。

2. **本地和线上共用同一个阿里云账号的频控额度。**
   本地狂点会挤掉线上的额度（1 条/分钟、5 条/小时、10 条/天），
   表现为「本地刚测过，线上就报 `biz.FREQUENCY`」。
   把常用测试号加进号码认证控制台「通用设置 → 测试号码白名单」（最多 300 个，不受流控）。
